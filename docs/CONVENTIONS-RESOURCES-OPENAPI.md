# Conventions — Resources & OpenAPI

Reference files:
`app/Api/Todos/Resources/TodoResource.php`,
`app/Api/Todos/Controllers/TodoController.php` (docblocks),
`app/OpenApi/OpenApiSpec.php`.

## Serialise through JsonResource — always

Controllers never return raw models or hand-built arrays. Every payload goes
through a `JsonResource` in `app/Api/<Module>/Resources/`,
named `<Resource>Resource` (`TodoResource`, `TodoCategoryResource`,
`TodoSubtaskResource`, `TagResource`).

```php
// app/Api/Todos/Resources/TodoResource.php
class TodoResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'title' => $this->title,
            'category' => $this->whenLoaded('category', fn () => new TodoCategoryResource($this->category)),
            'tags' => $this->whenLoaded('tags', fn () => TagResource::collection($this->tags)),
            'subtasks' => $this->whenLoaded('subtasks', fn () => TodoSubtaskResource::collection($this->subtasks)),
            // ...
        ];
    }
}
```

- Field names are the snake_case column names — resources mirror the database,
  not a presentation layer.
- Collections: `TodoResource::collection(...)` or
  `TagResource::collection(...)`, nested resources composed inside the parent.
- `data` stays null on deletes (see `ApiResponse`).

## `whenLoaded` — no N+1, no over-fetching

Optional relations are emitted with `whenLoaded(...)` so the payload contains
the relation **only when the service eager-loaded it** (see
[CONVENTIONS-SERVICES.md](./CONVENTIONS-SERVICES.md)):

```php
// Served only if TodoService loaded 'category' via ->with(['category', ...])
'category' => $this->whenLoaded('category', fn () => new TodoCategoryResource($this->category)),
```

This is the anti-N+1 discipline, inverted: the resource requests relations
lazily, and the service decides what to load. Never `$this->category` without
`whenLoaded` for an optional relation — it either forces an N+1 or bakes an
unloaded-value bug.

For required scalars (id, title, casts) direct access is correct and expected.

## OpenAPI is annotation-driven

The spec is generated by l5-swagger from `@OA` annotations in the code — there
is no hand-written `openapi.json` to keep in sync. Three layers:

### 1. Global spec — `app/OpenApi/OpenApiSpec.php`

`@OA\Info`, `@OA\Server(url="/api/v1")`, `@OA\SecurityScheme` (`sanctum`,
bearer), and the shared envelopes `SuccessResponse`, `ErrorResponse`,
`PaginationMeta`, `ValidationErrorResponse`. New shared schemas that multiple
resources reuse belong here. **Do not redefine the envelope per endpoint** —
reference it.

### 2. Per-resource schema — the resource docblock

Each resource carries an `@OA\Schema` describing its JSON shape, with
`nullable` on optional relations and enums on constrained fields:

```php
/**
 * @OA\Schema(
 *     schema="Todo",
 *
 *     @OA\Property(property="id", type="integer"),
 *     @OA\Property(property="title", type="string"),
 *     @OA\Property(property="category", ref="#/components/schemas/TodoCategory", nullable=true),
 *     @OA\Property(property="tags", type="array", @OA\Items(ref="#/components/schemas/Tag"), nullable=true),
 *     @OA\Property(property="created_at", type="string", format="date-time"),
 *     ...
 * )
 */
```

The schema name is the resource name (`Todo`, `TodoCategory`, `Tag`) — the
`ref="#/components/schemas/..."` targets used by controllers must match exactly
(`@OA\Schema(schema="Todo")` ↔ `ref="#/components/schemas/Todo"`).

### 3. Per-endpoint operation — the controller docblock

Every controller method carries the full operation annotation:

```php
/**
 * @OA\Post(
 *     path="/v1/todos",
 *     operationId="todoStore",
 *     summary="Create a new todo",
 *     tags={"Todos"},
 *     security={{"sanctum": {}}},
 *
 *     @OA\RequestBody(
 *         required=true,
 *         @OA\JsonContent(
 *             required={"title"},
 *             @OA\Property(property="title", type="string", maxLength=255),
 *             @OA\Property(property="priority", type="string", enum={"low","medium","high"}),
 *             ...
 *         )
 *     ),
 *
 *     @OA\Response(
 *         response=201,
 *         description="Todo created successfully",
 *         @OA\JsonContent(
 *             allOf={@OA\Schema(ref="#/components/schemas/SuccessResponse")},
 *             @OA\Property(property="data", ref="#/components/schemas/Todo")
 *         )
 *     ),
 *     @OA\Response(response=422, description="Validation error", @OA\JsonContent(ref="#/components/schemas/ErrorResponse"))
 * )
 */
```

Requirements:

| Annotation part | Rule |
| --- | --- |
| `path` | `/v1/<route>` — location, no query params |
| `operationId` | `<resource><Action>` camelCase, unique (`todoStore`, `todoAddSubtask`) |
| `tags` | plural resource name (`Todos`, `Libraries`) |
| `security` | `{{"sanctum": {}}}` on every authenticated endpoint |
| `@OA\RequestBody` | mirrors `FormRequest` rules exactly — required fields, enums, maxLength |
| `@OA\Response` | success response wraps `SuccessResponse` via `allOf` + a `data` property; error possibilities (`403`, `404`, `422`) reference `ErrorResponse` |
| status codes | match the controller (`201` on store, `200` otherwise) |

### Keeping rules and annotations in sync

The `@OA\RequestBody` and the `FormRequest::rules()` describe the same contract.
Change one, change the other, in the same commit — a mismatch is a spec bug that
frontend/typed clients hit immediately (see
[CONVENTIONS-REQUESTS-RESPONSES.md](./CONVENTIONS-REQUESTS-RESPONSES.md)).

## Verify the spec

After adding or changing annotations, regenerate locally
(`php artisan l5-swagger:generate`) and check the produced
`storage/api-docs/api-docs.json` for the new operation. Do not commit generated
artifacts unless the repo already does.

## Checklist

- [ ] Response built from a `JsonResource`, not raw data.
- [ ] Optional relations use `whenLoaded(...)`; services eager-load them.
- [ ] Resource carries an `@OA\Schema` with the matching schema name.
- [ ] Controller method has a full `@OA` operation (path, operationId, tags, security, request body, responses).
- [ ] OpenAPI request constraints match the FormRequest.
- [ ] New enums/nullability reflected in both schema and request-body annotations.
