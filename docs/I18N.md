# Translation guide

How user-facing copy gets into `resources/lang/<locale>/*.php` (`bot.php`,
`mail.php`, `notifications.php`, `widgets.php`). Binding for every change
that adds or changes a string. The `translator` agent
(`docs/agents/translator.md`) applies this guide; other agents hand
translation work to it instead of translating on the fly.

Envelope `message` strings are not in scope: they stay English (STANDARDS
Decisions).

## Workflow

1. The change adds or edits the string in `resources/lang/en/` (the source
   of truth). `de` too, if the author is sure of it. Bot strings also get
   their case in `app/Bots/Messages/SolytoMessage.php`.
2. The translator agent fills every other locale from the English string,
   following the voice, glossary and rules below.
3. Every locale has the same files and the same keys. Check (prints nothing
   when in sync):

   ```sh
   php -r 'foreach (glob("resources/lang/en/*.php") as $f) { $en = array_keys(require $f); foreach (glob("resources/lang/*", GLOB_ONLYDIR) as $d) { $g = "$d/".basename($f); $k = is_file($g) ? array_keys(require $g) : []; $x = array_merge(array_diff($en, $k), array_diff($k, $en)); if ($x) echo "$g: ".implode(", ", $x)."\n"; } }'
   ```

4. New terms that will come up again go into the glossary in the same change.

Adding a locale: add it to `config('app.locales')` and to the `language`
enums in the OpenAPI annotations (`grep -rn 'enum={"en"' app`), and create
`resources/lang/<locale>/`; the key check above only sees existing
directories.

The owner reviews `en` and `de`. Other locales are machine-translated by this
process; native-speaker feedback (issues, user reports) beats this guide and
goes into the glossary.

## Voice

- Informal, friendly, short. The app talks to one person about their own data.
- Informal address everywhere: `de` du, `fr` tu, `es` tú, `it` tu. Never mix
  within a language. Address the user directly ("Check your connection"), not
  impersonally.
- Write it as a native app in that language would, not as a word-by-word
  translation. Rephrase when the English structure sounds stiff.
- Button labels (mail buttons, bot keyboard options): verb in the imperative
  or infinitive as the language's apps usually do (`de` "Speichern",
  `fr` "Enregistrer", `es` "Guardar", `it` "Salva"). Keep the form
  consistent within a language.
- Sentence case for titles and labels unless the language capitalizes nouns
  (`de`).

## Rules

- **Placeholders** stay exactly as in English:
  - Laravel `:name` placeholders (`__('notifications.…', [...])`): same
    names, same count, order may change to fit the grammar. Keep the case of
    the name: Laravel treats `:Name` / `:NAME` as "capitalize" / "uppercase"
    the value.
  - `%s` / `%d` (bot strings filled with `sprintf`): same count and type,
    and the **same order**, since they are filled positionally. Rephrase the
    sentence so the order fits rather than reordering them.
  - Never translate or reformat them.
- **Line breaks**: keep `\n` sequences where English has them; those strings
  use double quotes so PHP turns them into newlines.
- **Quoting**: match the file — single-quoted strings escape `'` as `\'`.
  A syntax error breaks every locale, so the key check above must run.
- **Length**: titles and button labels should be at most ~30% longer than
  the English (push notification titles get cut off). If a word does not
  fit, pick a shorter synonym before abbreviating.
- **Punctuation**: follow the language's rules (`fr` a space before
  `? ! : ;`, `es` opening `¿ ¡`). Apostrophes stay straight (`'`), as in the
  existing files.
- **Brands and product names** stay untranslated: solyto, Telegram, CalDAV,
  CardDAV, WebDAV, iCal, Markdown.
- Do not touch keys outside the change, even if they look wrong. Report them
  instead.
